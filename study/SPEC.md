# Squad Rush — план 3D-плейабла (по референсам Top War: Battle Game)

Задание для модели-исполнителя (Sonnet). Работа ведётся собственными скиллами (в репозиторий не входят).
Проект: корень репозитория. Референсы: `study/ref/1.webp 2.webp 3.png 4.png`.
Готовый код прошлого проекта для подглядывания (env map, ACES, rim light, ghost play, `SIM.build()`):
соседний проект spire-smash (отдельный репозиторий) (`live/scene.js`, `live/sim.js`, `tools/build_playable.py`).

Решения, согласованные с пользователем:
- механика — **полный цикл Top War**: 1 боец → бочки с рекрутами → ворота, число на которых растёт от выстрелов → выбор
  оружия (AK / миниган) → волна красных → босс-гигант с HP → эндкард. Управление: свайп влево-вправо, стрельба авто;
- **свой бренд «Squad Rush»**: никаких логотипов, названий и UI Top War;
- полный цикл с эндкардом;
- модели — **гибрид**: свой отряд, рекруты и босс — CC0 Quaternius «Character Soldier» (skinned, с анимациями);
  красная толпа (и переполнение синего отряда) — процедурные чиби-инстансы;
- исход боя **зависит от игрока**: демо и средний игрок побеждают, слабый отряд → «SO CLOSE!» (тоже CTA);
  «фейк-фейл» уходит в A/B-вариант.

Фаза 0 уже сделана: проект создан `new.py`, `verify.sh` на нетронутом шаблоне зелёный (61 fps, 1.02 MB).
Порт 8960 занят сервером spire-smash → для этого проекта используй **8961**.

## 1. Что берём из референсов и что делаем лучше

| Референс | У нас |
|---|---|
| Реф.4: одинокий боец, бочки «3 1 3» с рекрутами наверху | Старт с 1 бойца; средняя бочка в его полосе, поэтому первый рекрут через ≈1 с даже без ввода. Рекрут машет (Wave), прыгает с бочки дугой в строй |
| Реф.2: красные ворота «−2», в них стреляют, и число растёт | Ворота — стекло в рамке. Каждые `GATE_STEP` урона дают +1; при переходе через 0 цвет плавно уходит из красного в синий; рябь от попаданий, пульс числа |
| Реф.1: бочки «20»/«46» с AK и миниганом наверху, зелёная обводка | Выбор оружия = выбор риска: дешёвая бочка AK или дорогая бочка минигана. Оружие крутится над бочкой с зелёной обводкой (inverted hull); при взятии весь отряд меняет ствол со вспышкой, «MINIGUN!», FOV-punch |
| Реф.1: убитые враги становятся белыми полупрозрачными «призраками» | Фирменная смерть красных: призрак поднимается и тает за 0.7 с, жёлтые кольца-искры попаданий |
| Реф.3/2: босс-гигант с полоской HP, толпа красных рядом | Босс = та же CC0-модель ×3, перекрашенная (красная куртка) + процедурные светлые волосы-шипы. Удары по земле с ударной волной, stagger каждые 25 % HP, slow-mo на смерти |
| Плоский фон шоссе / пустыни | Красный подвесной мост над морем (реф.2/4): порталы-башни, под которыми проезжает камера, тросы, море с бликами, силуэт города в дымке |
| В рекламе обещают то, чего нет в игре | У нас всё показанное играбельно; отмечать в выдаче нечего |

## 2. Механика (всё в `live/sim.js`: детерминированно, 120 Гц, без `Math.random`, только хэш `h1`)

**Мир** в sim-px, `U = 0.01` м/px. `x` вправо, `y` вниз; вперёд = вверх по экрану = `−y` (как в шаблоне).
Отряд пробегает дистанцию `d`, его центр стоит на `y = −d`. Дорога: `|x| ≤ K.RW = 330` (6.6 м).
Полосы: для двух объектов `x = ±165`, для трёх `x = −220 / 0 / +220`.

**Уровень — данные, которые строит `SIM.build()` из `K`.** Варианты A/B меняют `K` → уровень пересобирается.
Сразу допиши в `tools/build_playable.py` строку с `vjs`: `...; if (SIM.build) SIM.build(); ...` (так сделано в spire-smash).

| d (px) | ≈ t (с) | Секция |
|---|---|---|
| 0 | 0 | старт: 1 боец, винтовка |
| 650 | 2.2 | Ряд 1 (реф.4): три бочки `x = −220/0/+220`, HP `ROW1_HP = [4, 2, 4]`, на каждой рекрут (+1) |
| 1300 | 4.3 | Ряд 2: две бочки `x = ±165`, HP `ROW2_HP = 8`, на каждой по 2 рекрута (+2) |
| 2000 | 6.7 | Ворота (реф.2): слева синие `+2` (`GATE_L`), справа красные `−3` (`GATE_R`); каждые ворота занимают свою половину дороги |
| 2900 | 9.7 | Выбор оружия (реф.1): слева бочка `AK_HP = 20` с AK, справа `MINI_HP = 60` с миниганом |
| 3500–4300 | 11.7–14.3 | Волна: `WAVE_N = 40` красных колонной (`x ∈ [−200, 200]`, d 3800–4600); бегут навстречу, когда отряд ближе 1300 px |
| 4500 | 15 | Ворота-множитель (если `K.X2`): слева `×2` (фиксированные), справа `+3` (растут от выстрелов) |
| 4900 | 16.3 | Арена: дорога расширяется в площадку между двумя башнями, отряд за 1 с тормозит до стопа на d ≈ 5150 |
| 5150 + 450 | — | Босс + миньоны `MINION_N = 18` × 3 волны (`+0 / +2.5 / +5` с от входа в арену) |

**Отряд.**
- `S.units = [{ id, ox, oy, x, y, born, dead, from:[x,y], kind }]`.
- Слоты — филлотаксис вокруг центра: `r = SPACING·0.9·√i`, `φ = i·2.39996`, `SPACING = 52`. Юнит догоняет свой слот со скоростью `8/с`.
- `MAX_UNITS = 30`. Первые `CC0_MAX = 14` слотов (ближе к центру) рисуются CC0-ригами, остальные — синими чиби.
- Рекрут при рождении стартует из `from` (верх бочки или ворота) и за 0.45 с влетает в слот. Дуга по высоте — только в сцене.

**Управление.** Относительный свайп, `S.anc` из шаблона.
- На нажатии: `S.anc = { vx: inp.px, x0: S.tx }`.
- Пока держим палец: `S.tx = clamp(x0 + (inp.px − vx)·K.STEER, −RW + formR, RW − formR)`, где `STEER = 0.9` world px на view px, `formR` — радиус строя.
- Центр строя: `S.x += (S.tx − S.x)·min(1, FOLLOW·dt)`, `FOLLOW = 10`.
- Бег: `S.d += K.RUN·dt`, `RUN = 300`. В арене скорость плавно падает до 0.

**Оружие.**
`K.W = [{ name:'RIFLE', rate:3.5, dmg:1, spread:0 }, { name:'AK-47', rate:6, dmg:1.2, spread:0.035 }, { name:'MINIGUN', rate:12, dmg:1.6, spread:0.07 }]`.
- Юнит `i` стреляет, когда растёт `floor((t + 0.137·i)·rate)`. Фаза детерминирована, и сцена вычисляет вспышку ствола без состояния.
- Пуля: `{ x, y, vx, vy = −BUL_V (1700), dmg }`, разлёт из хэша, дальность `RANGE = 1050`.
- Каждый шаг пуля проверяет отрезок своего пути против целей в порядке близости по `y`. Попадает в первую, чей `x`-пролёт её накрывает.
- Попадание → запись в `S.hits` (кольцевой буфер на 96: `[x, y, hM, t, kind]`) для FX. В `S.ev` попадания не пишем.
- Оружие из бочки летит к отряду 0.4 с, потом `S.weapon = max(S.weapon, w)` → событие `weapon`.

**Цели.**
- **Бочка** `{ x, y, hp, hp0, w:150, reward:{recruit:n}|{weapon:w}, broken, lastHit }`.
  - `hp ≤ 0` → `barrel` + награда (`recruit` на каждого рекрута).
  - Если до бочки добежали, не разбив её, и строй её перекрывает: гибнет 1 ближайший боец, награда сгорает → `bump`.
  - HUD показывает `ceil(hp)`.
- **Ворота** `{ x, y, w:330, val, op:'+'|'x', hits, passed, lastHit, fixed }`.
  - Поглощают пули в своём пролёте. `hits += dmg`; каждые `GATE_STEP = 14` → `val += 1` (максимум `GATE_MAX = 15`) → `gateUp`.
  - Проход: центр строя пересёк `y` ворот внутри их пролёта.
  - Эффект: `val > 0` → +val рекрутов из ворот, `val < 0` → гибнет −val бойцов, `×` → count·val (с учётом `MAX_UNITS`). Событие `gate {val, op}`.
  - Пройти можно только одни ворота из пары.
- **Враг** (красный чиби) `{ x, y, hp: EN_HP (2), state, deadT }`.
  - Бежит к отряду со скоростью `EN_SPD = 170`, по `x` подтягивается к `S.x` с коэффициентом `EN_STEER = 0.6`.
  - Подбежал ближе `TRADE_R = 42` к юниту → гибнут оба → `trade`.
  - Убит пулями → `kill` (в сцене становится призраком).
- **Босс** `{ x:0, y, hp: BOSS_HP (≈1000), state: idle|walk|windup|stomp|stagger|rage|dead, t }`.
  - Вход в арену → `boss` (HUD: «BOSS FIGHT!», камера отъезжает).
  - Идёт со скоростью `BOSS_SPD = 70`. На расстоянии `BOSS_REACH = 240` от фронта строя начинает цикл: `windup` 0.5 с (на земле красное кольцо) → `stomp`, гибнут `BOSS_KILL = 2` ближайших. Перезарядка `BOSS_CD = 1.1` с.
  - Каждые потерянные 25 % HP → `stagger` 0.6 с (HitReact, откат на 40 px).
  - `hp ≤ 0` → `bossDie`, `S.winT`, slow-mo `SLOWMO = 0.35` на 0.9 с.
  - Slow-mo: всё движение в `step` идёт через `dt = DT·S.ts`, а `S.t` растёт на `DT`.
- **Фейк-фейл** (только вариант `K.FAKE_FAIL`): при `hp ≤ 12 %` → `rage`, CD 0.5 с, гибнут 3. Демо проигрывает, когда у босса остаётся ≈ 8 %.

**Конец.**
- Бойцов 0 → `S.loseT` → `end`, `endWhy = 'lose'` через `END_AFTER_LOSE = 1.4`.
- Победа → `'win'` через `END_AFTER_WIN = 2.0`.
- Таймеры шаблона: `END_NO_INPUT 12`, `END_IDLE 10`, `END_MAX 28` → `'time'`.

**`S.money`** = очки (`kills + 5·recruits`). Smoke-тест требует `money > 0`. Средняя бочка ряда 1 стоит в стартовой полосе, поэтому очки появляются даже без ввода.

**События (`S.ev`):** `recruit`, `barrel`, `bump`, `gateUp`, `gate`, `weapon`, `kill`, `trade`, `unitDie`, `boss`, `windup`, `stomp`, `stagger`, `rage`, `bossDie`, `win`, `lose`, `end`.
- `S.ev` обрезай до последних 4 с: убийств сотни.
- Для `demoCheck` и статистики веди `S.log`: время первого события каждого типа, счётчики `kills / trades / lost / recruits`.

**Контракт шаблона сохранить:** `create/step/at/spawn/respawn/demoCheck/scriptInput`, `S.end/endWhy`, `S.firstIn/lastIn`,
`VIEW`, `K`, `module.exports`, `S.cam` (точка взгляда, px) + `S.zoom`. Добавить `SIM.build`, `SIM.LEVEL`.

**Ghost play** (урок spire-smash): до первого реального касания, первые `GHOST_T = 2.0` с, отрядом рулит `scriptInput`.
Это не считается вводом (`firstIn` не ставится). Позиция «пальца» лежит в `S.demoX`: по ней HUD двигает руку.

**Attract-демо (`scriptInput`):** держит палец, `px = 540 + targetX / STEER`. `targetX(d)` плавно (smoothstep) идёт по точкам:
- ряд 1: центр, после разбития средней бочки → вправо, `+220`;
- ряд 2: `+165`, после разбития → `−165`;
- ворота: держит `−165` (синие) и настреливает их;
- после ворот → `+165` (миниган);
- волна: центр с лёгким покачиванием;
- `×2`: `−165`;
- босс: центр, лёгкое покачивание.

**`demoCheck`** (L = 30 с) должен выполняться:
- первый `recruit` ≤ 1.5 с;
- к 5 с собрано ≥ 5 рекрутов из бочек;
- ворота пройдены с `val ≥ +6`;
- `weapon` = MINIGUN в 8–11 с;
- в волне ≥ 85 % врагов убиты пулями, `trades ≤ 3`;
- `boss` в 15.5–17.5 с;
- бой с боссом 3.5–5.5 с, потери ≤ 4;
- `bossDie` ≤ 22 с, `end = 'win'` ≤ 24.5 с;
- ни одного `lose`.

**Модель обычного игрока** (урок spire-smash: без неё сложность «обрывом»). Напиши `tools/casual.mjs`, node, ~60 строк:
- 300 сидов, «игрок» из хэша: реакция 0.3–0.8 с, шум прицела ±70 px;
- с вероятностью 25 % цель выбирается «не ту» (ворота/бочка), 30 % не тянутся за второй бочкой;
- печатает: `win% / lose% / time%`, распределение оружия, средний отряд на входе в арену, медиана длительности боя с боссом.

Целевые коридоры (крути `MINI_HP`, `GATE_STEP`, `WAVE_N`, `EN_HP`, `BOSS_HP`, `BOSS_CD`):
- победа casual 60–75 %;
- миниган берут 40–60 %;
- отряд с AK и ~10 бойцами чаще выигрывает «на последних бойцах»;
- винтовка и ≤ 6 бойцов чаще проигрывают;
- любой бой с боссом кончается ≤ 10 с, эндкард ≤ 28 с от первого касания в любой ветке.

Настраивай **headless в node** (`SIM.at`, `SIM.step`), никогда по скриншотам. Если `SIM.at(L)` дольше 150 мс — разложи врагов по корзинам `y`.

## 3. Модели, сцена (`live/scene.js`), стиль и бюджет

**CC0-солдат (фаза 2, первый шаг).**
1. **Спроси пользователя** перед скачиванием: файл «Character Soldier» (Quaternius), poly.pizza/m/PpLF4rt4ah, CC0 1.0, GLB 1.33 MB, 7929 tris, анимированный.
2. `python3 polypizza.py get PpLF4rt4ah art/models_raw/soldier`.
3. Выведи имена клипов и костей (короткий node-скрипт на GLTFLoader или `npx gltf-transform inspect`).
4. Сопоставь роли в `scene.js` `const CLIP = {...}`:
   - RUN — бег со стрельбой (`Run_Shoot`/`Run_Gun`/`Run`);
   - SHOOT — стрельба стоя;
   - DEATH;
   - HIT;
   - WAVE — рекрут на бочке, эндкард;
   - WALK — босс;
   - ATTACK — удар босса.
   Не больше 6–7 клипов.
5. `node model.mjs art/models_raw/soldier/<file>.glb live/models/soldier.glb --clips <...> --tris 3000` → цель ≤ 260 KB.
6. Запасные варианты:
   - Quaternius «SWAT» (poly.pizza/m/Btfn3G5Xv4, CC0, 1.56 MB) — тоже спросить;
   - на крайний случай — шаблонный `worker.glb` (CC0, уже в проекте) с перекраской и процедурной каской.
7. Запиши в `tools/build.json` → `models.soldier` (автор, лицензия, ссылка, клипы). Удали `worker` из `models` и `live/models/worker.glb`, `coin` — из `images`.

**Как живут риги.**
- Пул `CC0_MAX + 3` клонов `KIT.rig`, все создаются один раз в `init`.
- Слот закрепляется за `unit.id`, чтобы анимация не прыгала. Освобождается через 1.2 с после смерти: тело опускается под дорогу и тает.
- Порядок раздачи слотов: отряд → рекруты на бочках → ничего.
- Перекраска командой: `model.mjs` сводит материалы в одну палитру-текстуру. Нарисуй её копию в canvas и замени ячейки по ближайшему цвету: синий отряд — каска `#2F7DE1`, форма `#E3C9A0`, штаны `#2E5FB8`; босс — куртка `#D03A33`. Это `CanvasTexture`, sRGB, `NearestFilter`.
- **Расширь GENERIC `KIT.rig`** опцией `once` для одноразовых клипов (Death, Attack): время зажимается в `dur − 1e-3`, а не зацикливается. Пометь комментарием.
- Оружие в руках — по `KIT.Pool` на тип ствола (3 draw на весь отряд). Матрица = `handBone.matrixWorld × offset`, считается после `mixer.update(0)` + `root.updateMatrixWorld(true)`. Кость ищи по `/hand.?r|fist.?r|righthand/i`.

**Процедурные чиби** (красные враги + синее переполнение).
- По 3 `InstancedMesh` на команду:
  - верх: торс + голова + каска, ~110 tris;
  - ноги (одна геометрия, 2 инстанса на чиби);
  - руки.
- Пропорции и цвета сними с CC0-модели после импорта: голова/каска крупные, иначе синие чиби в отряде будут выпадать.
- Красные: каска `#D93A2F`, голый торс/майка `#E8C9A0`, шорты `#B8322A`, кожа `#F2B48C`.
- Бег кодом: ноги ±40° на 2.6 Гц, фаза из `h1(id)`; руки в противофазе; подпрыгивание `|sin|·0.04` м; наклон 10°.
- Смерть красного — **призрак** (реф.1): отдельный `Pool` той же геометрии в позе «раскинул руки», `MeshBasic` белый, opacity 0.4, `depthWrite false`. Поднимается на 0.8 м, растёт ×1.2 и тает за 0.7 с, плюс белое кольцо-пуф.
- Тени чиби — blob-`Pool` (1 draw), shadow map они не отбрасывают.

**Процедурный мир** (0 байт ассетов; `KIT.merge` / `KIT.Field` / `KIT.Pool`).
- **Дорога:**
  - плоскость с canvas-текстурой: асфальт `#8D939C` + шум, белые края, пунктир по центру; repeat по Z, 1 draw;
  - бордюры `#C9CED6`;
  - красные перила моста `#C8352B`: стойки через `Field` по Z-чанкам + 2 длинных бруса.
- **Башни-порталы** на d 1500, 3500 и пара у арены (≈4950):
  - две красные колонны 0.8×12 м за перилами (`x = ±4.2` м) из моря;
  - 2 поперечины над дорогой на 7 и 11 м — камера проходит под ними;
  - всё в 1 mesh, инстансы через `Field`.
- **Тросы:** провисающие `TubeGeometry` r = 0.08 м между верхушками башен, по 1 merge на пролёт; вертикальные подвесы через `Field`.
- **Море:** плоскость на Y = −10 м, `#2A7FC4` → у горизонта `#8CC4E8`; canvas-текстура ряби со смещением UV = `t·speed` (без состояния).
- **Город:** merge из боксов `#5D7290` на ±60 м, тонет в тумане.
- **Небо:** `scene.background` — canvas-градиент `#7FBFF0` → `#D9ECF7`.
- **Туман:** `#CFE6F5`, near 25 м, far 80 м.
- **Бочка** (лежит, ось вдоль X, как в реф.1/4):
  - цилиндр r 0.55 × 1.3 м, 16 клёпок двух коричневых `#C0773A/#A9652F` (vertex colour), 2 стальных обруча `#8A8F99`, тёмные торцы;
  - 1 геометрия, все бочки в одном `Pool`;
  - попадание: squash 1.06 → 1 за 80 мс от `lastHit`, белая вспышка цвета инстанса, щепки;
  - разлом: 8 клёпок разлетаются (`Pool`) и **остаются лежать** на дороге (append-only — след в мире), пыль.
- **Оружие** (процедурное, общая геометрия для пикапа ×2.5 и для рук ×1):
  - AK: ствольная коробка `#3A3D42`, дерево `#A0522D`, изогнутый магазин;
  - миниган: 6 стволов кругом, барабан, синие акценты `#2F7DE1`;
  - пикап крутится, зелёная обводка (BackSide-копия ×1.06, emissive `#3DFF6A`), светящийся круг под ним.
- **Ворота** (реф.2):
  - 2 стойки + балка (синие `#3BA0FF` / красные `#FF3B30`, цвет лерпится по `val`);
  - панель `MeshBasic` transparent 0.45, `depthWrite false`;
  - рябь-кольца от попаданий (`Pool` на плоскости панели);
  - при проходе — всплеск частиц цвета ворот;
  - число рисует HUD.
- **Босс:**
  - CC0-риг ×3, свой материал (перекраска + `emissive` для вспышки попаданий);
  - процедурные светлые волосы-шипы `#F2B640` (конусы, merge), прицеплены к кости головы;
  - удар: кольцо ударной волны на земле (расширяется), shake 0.25 м, 2 бойца отлетают;
  - смерть: Death-клип в slow-mo, большая пыль.
- **FX-пулы** (все без состояния, из `S` и `S.hits`):
  - трассеры — аддитивные вытянутые квады `#FFC24A` 0.35 м;
  - вспышки стволов по фазе стрельбы;
  - жёлтое кольцо-искра на попадании (реф.1);
  - щепки, пыль;
  - гильзы — латунные цилиндрики, у минигана поток;
  - конфетти на победе;
  - кольцо-предупреждение `windup`.
- **Свет и картинка:**
  - Hemisphere `#BFE3FF` / `#6B7380`, 0.7;
  - Directional `#FFF1DC`, 1.6, сверху-слева-спереди, тень 1024, бокс ±9 м за точкой взгляда;
  - ACES, exposure 1.05;
  - env map и rim light — как в spire-smash (на Gate A критик за них прибавил баллы);
  - тени отбрасывают отряд, босс, бочки, ворота, башни. Если draws > 75 — отряд переводи на blob-тени.
- **Камера:**
  - сзади-сверху, pitch −52°, FOV 42;
  - точка взгляда = центр отряда + 3.5 м вперёд, по X следует за отрядом на 40 %;
  - отряд стоит на 70–76 % высоты экрана, дорога заполняет ширину;
  - `S.zoom` отъезжает с ростом отряда (до 0.85) и в арене (0.78, чтобы влезли босс и отряд);
  - shake от событий, FOV +4° на 0.3 с на `weapon`.
- **Эндкард 3D:** затемнение. `win`: отряд на подиуме играет WAVE + конфетти, босс лежит. `lose`: над экраном возвышается босс.
- `probe()`/`QA()` сохранить:
  - hero-бокс = видимый отряд (у одинокого бойца на `start` ≈ 9–11 % — это нормально, запиши в PLAN.md);
  - QA-состояния: `start`, `recruit`, `gateShoot`, `choice`, `minigun`, `wave`, `bossIntro`, `bossFight`, `bossDie`, `endcard_win`, `endcard_lose`, `endcard_time`;
  - для `lose` прогони заскриптованного «плохого» игрока: стоит в центре, ворот не трогает, берёт AK или ничего.

**Бюджет** (`probe.mjs`):
- draws ≤ 75 вместе с тенями;
- tris ≤ 250k;
- hero 15–22 % высоты в бою;
- 60 fps на 390×844;
- сборка ≈ 1.0 MB: three 0.68 + код 0.05 + soldier ≤ 0.26 → влезает в лимит Meta 2 MB.

## 5. Фазы и критерии готовности

Одна фаза — одна сессия. Состояние держи в `study/PLAN.md` (≤ 40 строк). Этот файл — полная спецификация, его не сокращай.

**Фаза 2 — модели и вид (Gate A).**

**Фаза 3 — HUD, звук, сочность (Gate B).**

Затем `python3 tools/build_playable.py --variant all`.
Выдача пользователю (по-русски, коротко): что попробовать, размеры по сетям из `dist/*/report.md`, fps, draws/tris, оценки критиков, итоги `casual.mjs` по вариантам, пробелы, следующий шаг.

## 6. Правила для исполнителя

- Экономия токенов обязательна:
  - мелкие `Edit`, не перечитывать только что записанное;
  - картинки — только на гейтах (один даунскейл-шит);
  - числа — через `verify.sh`, `probe.mjs`, `casual.mjs`.
- `kit.js` и `tools/*` не форкать, только расширять (`KIT.rig` `once`, `SIM.build()` в сборке). Generic-добавки помечай комментарием.
- Сцена и анимации — чистая функция `(state, t)`. Никакого `Math.random` и накопительного состояния в `scene.js`: probe и `render.mjs` рендерят произвольный момент.
  - Исключение — кэш «какой риг у какого `unit.id`»: он детерминированно восстанавливается из `S.units`.
- Скриншоты WebGL — только через `__renderAt` / `__probe(name, true)`, иначе получится чёрный кадр.
- Никаких внешних запросов в билде. Каждое скачивание модели — сначала спросить пользователя (файл, источник, размер, лицензия).
- Не обещать в рекламе того, чего нет в игре.
- Неясно и влияет на результат → спросить пользователя. Иначе выбрать разумное и записать в PLAN.md.
